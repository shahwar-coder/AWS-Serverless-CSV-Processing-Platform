# Context Management

1. **Local AWS foundation**: `application/common/config.py` centralizes Floci endpoints and resource names. The resource scripts idempotently manage input/results S3 buckets, the DynamoDB jobs table, the processing SQS queue, and the input-bucket `ObjectCreated:Put` notification.
2. **HTTP API**: `application/scripts/deploy_local_backend.py` deploys four Python Lambda functions, an API Gateway HTTP API, and the SQS event source mapping. Public routes are `POST /jobs`, `GET /jobs/{job_id}`, and `GET /jobs/{job_id}/result`. The local Floci route template uses `jobId` internally because its current path-regex parser rejects underscores; clients still send a normal job ID URL segment.
3. **Create and upload**: Create Job validates `filename` and `content_type: text/csv`, conditionally writes `UPLOAD_PENDING`, and returns a 900-second signed PUT URL for `uploads/{job_id}/input.csv`. Lambda uses the internal Floci endpoint, but signs upload URLs for `localhost:4566` so the client can reach them. The browser uploads directly to S3.
4. **Processing and result**: S3 notifies SQS, which invokes the worker. A conditional, expiring claim changes `UPLOAD_PENDING` to `PROCESSING`; its lease, attempt count, duplicate handling, and transient retries remain internal. The worker reads S3 metadata and persists `uploaded_at` and `file_size_bytes` even if CSV validation fails. It accepts required `product,quantity,price` headers in any order with extra columns, counts valid nonblank data rows, and groups trimmed product names case-insensitively. A successful INR report contains exact Decimal revenue, totals, and all product aggregates. Inputs over 5 MiB or 1,000 distinct products fail validation. Invalid CSV sets `FAILED`; there is no `QUEUED` state. The result route returns JSON only for `COMPLETED` jobs (`409` otherwise, `404` for unknown jobs).
5. **Verification and UI**: Focused tests and fixture-driven HTTP E2E tests cover Create Job, DynamoDB, presigned PUT, S3, worker completion and failure, job metadata, and result retrieval. Tests clean up their jobs and objects and do not manually receive SQS messages. The minimal React UI runs on port 5173, proxies `/api` to Floci locally, PUTs directly to S3, and reads the revised summary fields. Browser visual verification remains open.
